# AI 截图解析待办 · 产品与技术计划

> 文档版本：v1.0 ｜ 提案日期：2026-09-18
> 需求：设置中支持填写智谱 / MiniMax（Coding Plan）的 Key 与模型；全局快捷键截图；AI 识别截图内容自动生成待办；自动解析象限，无法解析时默认第四象限。

## 一、用户流程（目标体验）

```
按下快捷键（默认 ⌥⌘S）
   → 屏幕变暗，拖框选择截图区域（Esc 取消）
   → 自动请求 AI 解析（墨晕动效 + 进度提示）
   → 弹出「识别结果」面板：任务列表（标题 + 象限，可逐条修改/勾选）
   → 点击「添加」批量入待办（复用现有入场 stagger 动画）
```

设计原则：**截图内容只在用户主动触发时发送**；解析结果必须经用户确认才入库；AI 无法判断象限时静默落入「不重要 · 不紧急」。

## 二、技术方案

### 1. AI 服务商抽象（AIProvider）

智谱与 MiniMax 的对话 API 均为 OpenAI 兼容格式，统一为一个协议：

| 项 | 智谱 GLM | MiniMax |
| --- | --- | --- |
| BaseURL | `https://open.bigmodel.cn/api/paas/v4` | `https://api.minimax.chat/v1` |
| 接口 | `POST /chat/completions` | `POST /text/chatcompletion_v2` |
| 认证 | `Authorization: Bearer <key>` | 同左 |
| 视觉输入 | **GLM-5.3-flash**（`image_url: data:image/png;base64,...`） | **minimax-m3**（同格式） |
| 输出 | 文本，约定 JSON | 同左 |

- `AIProvider` 协议：`send(system:prompt:imageData:) async throws -> String`
- 内置智谱 / MiniMax 两个实现 + 「自定义」选项（BaseURL / Model 可填，兼容任何 OpenAI 风格端点）
- 预置模型下拉：智谱默认 `GLM-5.3-flash`，MiniMax 默认 `minimax-m3`（均已确认可用）；仍允许手填任意模型名，以兼容订阅内其他模型

### 2. 截图（关键依赖：屏幕录制权限）

- 全局快捷键：Carbon `RegisterEventHotKey`（无第三方依赖），默认 `⌥⌘S`，设置中可改
- 选区 UI：透明覆盖窗口（全屏、半透明遮罩、拖框高亮、Esc 取消、尺寸提示）
- 取像：`CGWindowListCreateImage` 截取屏幕选区 → PNG（Retina 2x）
- **权限（TCC）**：屏幕录制属「隐私与安全性」授权，首次触发时检测 `CGPreflightScreenCaptureAccess()`，未授权则弹出引导页（附「打开系统设置」直达按钮）
- 备选通道：`screencapture` 命令行（同样受 TCC 约束，作为降级实现保留）

### 3. AI 解析与象限判定

System Prompt 约定输出严格 JSON：

```json
{"tasks":[{"title":"…","important":true,"urgent":false}]}
```

- 解析规则：仅取 `title` 非空条目；`important/urgent` 缺失或非法 → 均按 `false` 处理 → **默认落入第四象限（不重要 · 不紧急）**
- 四象限映射：`重要+紧急→立刻做`，`重要+不紧急→计划做`，`紧急+不重要→委托做`，其余→第四象限
- 健壮性：30s 超时；响应截断/JSON 损坏自动重试 1 次（附「请只输出 JSON」纠正提示）；仍失败则提示错误原因（Key 无效 / 额度不足 / 网络）
- 单图体积控制：PNG 截图压缩至长边 ≤ 1600px 再 base64

### 4. 设置界面（SettingsView 扩展）

```
AI 截图解析
├─ 服务商：智谱 ｜ MiniMax ｜ 自定义
├─ API Key：••••••••（存入 Keychain，不落明文）
├─ 模型：下拉预置 + 可手填
├─ 截图快捷键：⌥⌘S（点击重录）
├─ [测试连接] → 成功/失败提示
└─ 隐私说明：截图仅在你按下快捷键时发送给所配置的服务商
```

- Key 存 **Keychain**（Security 框架），其余存 UserDefaults
- 「测试连接」发送极小请求验证 Key/模型有效性

### 5. 数据与动效

- 识别结果面板：每条任务带四象限选择器（复用现有配色语言）、复选框；「添加」后走现有 `store.add` + 入场 stagger 动画
- 等待动效：复用墨晕视觉语言（呼吸辉光），遵循「减弱动态效果」降级

## 四、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 屏幕录制权限（TCC）未授权 | 截图不可用 | 首次使用引导页 + 检测 API + 系统设置直达 |
| 视觉请求格式与两家端点的细节差异 | 解析报错 | 已确认支持的模型：智谱 `GLM-5.3-flash`、MiniMax `minimax-m3`；模型可自填，「测试连接」即时验证 |
| 两家视觉模型 JSON 遵从度差异 | 解析失败率 | 严格 Prompt + 重试 + JSON 容错；失败兜底第四象限 |
| 截图隐私顾虑 | 用户信任 | 仅手动触发发送；设置页明示；Keychain 存 Key |
| 全局快捷键冲突 | 快捷键无效 | 注册失败时提示换键；可在设置中自定义 |

## 五、验收标准（v1.2.0）

1. 配置智谱或 MiniMax 的 Key/模型后，「测试连接」通过
2. ⌥⌘S → 框选 → 8 秒内返回识别结果（视网络与服务商）
3. 截图含清晰待办文字时，识别 ≥ 1 条任务；AI 未给象限的任务 100% 落入第四象限
4. 确认面板可改象限、可勾选、批量添加后计数与动画正确
5. Key 重启后仍有效（Keychain）；错误路径（错 Key / 断网 / 超时）均有明确提示且不崩溃
